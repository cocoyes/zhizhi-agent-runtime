# On-demand Skills Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Load local Skill metadata and expose bounded search and explicitly selected execution.

**Architecture:** A public skill catalog owns atomic disk snapshots and deterministic search. Request-scoped grants and invocation continuations bind the two fixed tools to the existing model, registry and budgets. Composite tool results carry nested facts and suspension through every execution path.

**Tech Stack:** Go, existing yaml.v3, existing ReAct runtime and checkpoint store.

**Spec:** docs/superpowers/specs/2026-10-31-skills-design.md (approved in chat).

## Global Constraints

- Default search limit 5, maximum 10; selection TTL 15 minutes.
- File limit 1 MiB, front matter 64 KiB, root count 10,000, depth 32.
- Internal iterations 8, tool calls 16, execution depth 1.
- Metadata stays in memory; full catalog is never sent to the model.
- Preserve existing APIs and no-Skill checkpoint compatibility.
- Only targeted tests during development; no unnecessary builds or repeated suites.

## Review Focus

- Failed reload leaves the previous root intact: catalog test.
- Selection cannot cross request scopes: scope test.
- Resource paths cannot escape through symlinks: resource test.
- Confirmation after partial execution cannot repeat writes: runtime resume test.
- A checkpoint after search but before invoke retains grants: runtime checkpoint test.
